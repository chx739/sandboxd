# Phase 8：Kubernetes / Prometheus 运维 Agent 完整目标与验收

> 2026-09-29 用户确认的当前实施目标。本文件是 `GOAL.md` 的 Phase 8 细则和跨会话恢复依据。不能用进度工具中的短摘要删减本文件的范围。Phase 7 的代码、文档、数据和历史测评保留，但 Phase 7 的 Jev 待办不属于本轮。

## 1. 最终目标与边界

在 `chx739/sandboxd` 完成 Python 为主的 Kubernetes / Prometheus 告警排障 Agent MVP：**可运行、可复现、可测评，能说明技术取舍和失败案例，适合秋招讲解**。不追求生产级高可用、多租户或自动修复。Go sandboxd 的既有执行安全边界、审批门和历史证据保持有效。

开工先核对现有实现、环境、数据和报告，逐项记录“已完成 / 要调整 / 尚未实现”；复用 Phase 7 的会话树与记忆，不重复造轮子。Python 和 Milvus **2.5.10** 固定；其他新依赖固定兼容版本并锁定。沿用手写 Agent Loop，不为了本轮引入 LangGraph；如确有必要调整依赖，记录收益和代价。阶段性小提交推送到独立开发分支，更新或创建可审查 PR，**不自动合并**。不直接删除旧索引、Docker 卷、历史报告和用户已有修改。

**Jev 不在本轮范围内：不实施、不调试、不调用、不作为验收条件。** 已有 Jev 代码和旧证据保留为历史。默认演示和测评不依赖 Jev。旧 ES 知识检索在迁移完成前是历史基线；新默认知识库路径不依赖 ES。OpenSearch 用于日志检索与聚合。

## 2. 功能交付

### 2.1 树形会话管理

参考 Pi Agent 源码，核对并完善已有节点、父子关系、活动叶子、从完整 Turn 创建分支、切换分支、重启恢复和当前路径上下文。其他分支不能泄漏到当前上下文；工具调用与结果要成组保存。旧线性 Session 保持可读，截断尾记录能安全处理。恢复只恢复脱敏上下文，生成新的 Task 与 Sandbox，绝不重放历史工具副作用。给出自动化验证和分支/恢复演示命令。

### 2.2 Agent 分层记忆

参考 Codex 开源源码，核对并完善原始会话与来源、会话摘要、候选记忆、整理后的长期记忆和有预算限制的按需加载。保留来源、时间、冲突、重建、遗忘；只有适合的完整已结束会话可进入记忆。注明参考仓库、commit、文件及本项目的简化差异。若抽取仅靠规则或显式标记，必须如实写明其边界。会话和记忆的持久化原件与可重建的检索索引分工明确。

### 2.3 运维知识库 RAG

知识库主链路为 **Milvus 2.5.10 内置 BM25 + Dense → RRF → BGE Reranker → 带来源回答**。从已有 ES BM25 + Milvus Dense 双索引路径迁移；默认知识库不需要 ES。提供最小导入、更新、删除、重建能力；支持组件、来源和适用版本等必要过滤。文档和片段保留稳定 `doc_id`、章节标识、来源 URL、固定内容版本和证据定位。记录 Embedding、Reranker 和分词配置的实际版本；中文问题检索英文文档的效果单独评估。

固定约 **30–50 篇**有效文档，首选 Prometheus Operator Runbooks、Kubernetes 官方排障文档及项目故障记录。聚焦容器反复重启、Pod 未就绪、Service 访问异常、资源压力等故障。保存许可、来源、抓取/源码版本和内容快照；运行中的上游文档更新不能悄悄改变测评语料。按章节切块，尽量保留“症状—检查—解释”关系。知识检索结果始终是低信任数据，不能成为 System 指令或授权。

### 2.4 OpenSearch 日志查询

OpenSearch 保存固定 JSON 日志及运行事件，支持按时间、服务、级别、错误码、`trace_id` 等字段查询，以及计数、分组、时间聚合。结果带稳定日志 ID、时间和实际查询条件，供 Agent 引用。第一版提供受限结构化 `search_logs`、`aggregate_logs`，由 Python 转换成 OpenSearch 查询；无需自由生成完整 DSL/PPL。注明每批日志来自真实公开集、合成夹具、回放还是实际故障采集。

### 2.5 联合排障

至少三类故障跑通：用户描述异常 → Agent 查现场日志 → 结合异常查知识库 → 输出已观察事实、可能原因、下一步验证和两类证据引用。证据不足时指出缺失信息，不把可能原因写成已确认根因。回放必须标记为回放；未执行真实恢复动作时，不宣称自动修复成功。

## 3. 测评与验收数据

所有报告分开标注 **确定性测试、真实本地服务集成、回放、真实外部模型、模型裁判、人工审核**。固定数据快照、模型版本、随机种子、硬件、参数和命令；保留原始逐题结果与失败案例。不用单一综合分取代分层指标。

### 3.1 会话与记忆

覆盖分支隔离、重启恢复、完整 Turn/工具组、旧格式与截断尾、记忆来源、冲突、重建、遗忘、上下文预算。自动化断言明确哪些仅是规则提取/合成数据，不宣称自然语言记忆抽取的实际效果。

### 3.2 运维 RAG

交付 **60 个问题**，覆盖告警名/错误码精确查询、症状口语改写、排查步骤、多文档综合、信息不足和知识库无答案。每题有相关文档与证据章节、参考答案关键事实与步骤、需要继续获取的信息及不得作出的结论。区分人工编写、模型生成候选、已审核状态；生成题由人工核验，不能把模型候选称为人工金标。开发集与测试集分离，同题改写归入同一集合；测试 QA 不得入知识库。相关性标签优先绑定稳定文档段落，再映射到 chunk。

用相同语料和问题比较 **BM25、Dense、BM25 + Dense + RRF、Hybrid + BGE Reranker**。报告 Recall@5/10、MRR、nDCG@10、检索/重排/端到端 P50/P95、资源占用和成本。再比较无检索回答与 RAG 回答；使用 Ragas 忠实度、事实正确性等指标，并评估关键步骤覆盖、引用有效性、适用条件及无依据确定性结论。模型裁判保存依据并人工抽查，报告独立于确定性检索指标。

### 3.3 日志查询

交付 **30–50 个问题**，覆盖精确 ID/错误码、时间窗口、计数、分组、上下文和无结果。固定“当前时间”、时区、区间端点、排序与分页。由独立 Python / DuckDB 逻辑计算预期日志 ID 集及数值，避免用同一 OpenSearch 查询自证正确。比较执行结果而非 DSL 字符串，报告日志集合 Precision/Recall、聚合正确率、时间条件与工具参数正确率、延迟；近似聚合预设容差。

使用 OpenSearch Benchmark 的 `http_logs` 或与本项目日志结构匹配的自定义 workload，做有界性能测评。报告数据量、并发、预热、硬件、吞吐、P50/P95/P99、错误率和资源占用。小规模本地结果不外推为生产 SLA。

### 3.4 联合 Agent

分别评估工具选择、参数、必要现场证据、适用文档、引用，以及事实/假设/待验证区分。回放与真实模型报告分开；固定模型、输入、调用上限、超时和费用。无条件执行的恢复操作不在范围内。

## 4. 环境、费用和安全

检查 Docker、WSL、Python、GitHub CLI、模型缓存、端口和内存后复用已有服务；避免占用其他项目资源。密钥只从已授权的仓库外配置读取，不展示、不提交、不写入日志。先完成无 API 费用的测试、回放和本地服务测评。真实付费 LLM/裁判调用前核对本任务明确授权；若模型、调用次数或费用上限未获授权，先完成全部独立工作，并列出精确待执行计划。已有历史 Live 授权不自动覆盖新评测。调用必须有超时、零或有界重试、次数/费用止损。绝不调用 Jev。

## 5. 结构化文档与完成判据

维护两类文档：一类供后续 Agent 恢复，记录目标、范围、状态、环境、版本、启动命令、决策、阻塞和结果路径；另一类供用户学习与面试，解释整体架构、Pi/Codex 源码参考和简化、Milvus BM25/Dense/RRF/BGE、OpenSearch 日志职责、数据流、测评口径、消融结果、真实坑、技术取舍、一分钟讲法、限制及后续改进。`docs/PROGRESS.md` 始终写清第一项未完成工作。

完成须同时交付：可重复的安装/启动/导入/演示/测评命令；四部分可运行实现及三类联合故障；固定数据清单、60 题 RAG 和 30–50 题日志评测及原始结果；必要的自动测试、消融、性能报告和失败分析；学习文档与恢复记录；已推送的可审查 PR。README 中的能力状态必须与验证证据一致。仍需人工审核或新授权的真实调用，明确列为剩余项，不能虚构通过或提前宣布完整验收。
