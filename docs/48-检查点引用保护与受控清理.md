# 检查点引用保护与受控清理

> Phase 9 V2，规格以文档43为准。当前交付本地引用投影、保留标记、离线预览和遗忘控制协议；实际Go/restic forget/prune接线及真实清理验收尚未完成。默认不删除任何快照。历史真实服务证据见文档47。

## 1. 为什么不能按checkpoint_id直接删除

多份联合检查点可能指向同一个restic快照；仓库逻辑名称也可能是同一仓库的别名。清理以`repositoryCryptoId + 完整snapshotId`为组，检查所有已知引用。即使选中的checkpoint不是当前head，只要同组另一份是head，该快照仍受保护。

本账本只掌握当前控制目录的引用，不枚举MinIO对象，也不能授权删除其他部署或未知快照。后端还要核对固定仓库身份、真实snapshot及跨维护操作的串行屏障。不能用“本地预览eligible”替代这些执行证明。

## 2. 哪些引用必须保护

| 来源 | 当前处理 |
|---|---|
| 每条保留分支的head | 整组禁止遗忘 |
| 显式pin | 持久化`checkpoint.pin`；unpin只解除这一类引用 |
| 已保留恢复请求的source | RESERVED/FILES_READY/ATTACHED/FAILED都保留来源引用；没有自动释放功能 |
| 正在保存的检查点 | PREPARING/DATA_READY使预览暂时阻止所有清理 |
| 活跃历史恢复 | RESERVED/FILES_READY暂时阻止所有清理 |
| FAILED但已有data的检查点 | 已知孤立数据保留，不能当普通已提交旧版本清理 |
| 无法验证的Session引用 | 阻止该组清理，先查明控制数据问题 |
| 不在账本中的后端对象 | 不列作候选，不手工删除对象或哈希块 |

清理预览包含固定格式原因、完整组成员、逻辑仓库别名及当前文件恢复资格。没有用户自由文本原因、凭据、仓库URL或完整消息内容。

## 3. 历史提交与文件恢复资格分开

```text
历史checkpoint.state：COMMITTED，原件一直保留

文件资格：available
             ↓ checkpoint.forget PREPARED，fsync
         forget-pending
             ↓ 可信执行器实际forget成功后，写FORGOTTEN
          forgotten
```

- `prepare_forget`接受UUIDv4 gcId、精确仓库/快照及预览SHA256；重新计算当前预览，拒绝过期、被保护、未知或并发清理目标。
- 一条PREPARED同时绑定整组checkpointIds，先停止它们的文件恢复资格，再允许后续协调器执行删除。相同请求重试不重复追加；改绑定拒绝。
- `restore_point`、按旧node选检查点及新恢复请求都会检查文件资格。历史消息树与原始COMMITTED记录仍可读，不偷偷改用邻近文件版本。
- PREPARED后进程崩溃、后端失败或结果未知时，保持不可恢复及禁止新保存的状态，等待同一个管理请求对账；不能自动回滚为available。
- `complete_forget`是内部控制方法，本身不证明后端删除成功。目前只有合成测试使用它，没有HTTP/模型工具或CLI apply入口；未来可信协调器核验实际结果后才能调用。
- FORGOTTEN后不允许重新绑定同一已遗忘snapshot，后续正常新检查点可以继续沿当前未删除head递增revision。

预览SHA是当前引用投影的内容校验，不是授权令牌；日志checksum同样不是防恶意管理员的签名。原JSONL单写入锁、fsync和完整坏记录拒绝继续生效。新事件启用后不要交给不识别pin/forget事件的旧版本写入。

## 4. 可运行管理命令

先停止同控制目录的agentd；文件锁占用时命令拒绝，不接管或强制解锁。仅访问已存在的WSL原生私有控制目录，不自动初始化。

```bash
agentd/.venv/bin/python -m agentd.checkpoint_admin \
  --checkpoint-dir "$HOME/.local/share/sandboxd/<部署控制目录>/checkpoints" preview

agentd/.venv/bin/python -m agentd.checkpoint_admin \
  --checkpoint-dir "$HOME/.local/share/sandboxd/<部署控制目录>/checkpoints" pin 'cp-<uuid4hex>'

agentd/.venv/bin/python -m agentd.checkpoint_admin \
  --checkpoint-dir "$HOME/.local/share/sandboxd/<部署控制目录>/checkpoints" unpin 'cp-<uuid4hex>'
```

preview以只读文件描述符打开日志，保持排他文件锁，不chmod、不修断尾、不追加日志；pin/unpin使用正常单写入流程。读文件可能更新文件系统atime，不能把它描述为所有文件系统元数据都静止。两种模式都不访问NFS/MinIO、不调模型、不执行restic、不删除Session引用。

## 5. 代码阅读顺序与验证范围

1. `app/runtime/checkpoints.py`：`protected_checkpoints`→`cleanup_preview`→`prepare_forget`→`file_availability`→事件校验与重建。
2. `app/runtime/durable.py`：正常单写入与只读打开、flock、checksum、fsync及断尾处理。
3. `checkpoint_admin.py`：固定preview/pin/unpin，现有控制目录检查。
4. `tests/test_checkpoint_retention.py`：别名共享保护、显式pin/过期预览、恢复源、未提交数据、遗忘中断重建、伪造完整事件拒绝、只读预览/活跃实例拒绝。

测试直接提交的快照和FORGOTTEN均为合成身份，没有执行真实删除。旧真实控制目录可用于只读CLI兼容验证，但它不能代替新的真实forget/prune实验。

面试问答：**为什么COMMITTED仍不能恢复？** COMMITTED证明历史上的联合提交成立；文件是否仍被保留是另一条生命周期。先记录遗忘意图，使恢复接口拒绝，再删除后端对象，可避免进程在删除后崩溃却仍把旧快照列为可恢复。

## 6. 下一步仍需完成

- 可信Go固定维护执行器的forget/prune及全局串行化；不能让Python提交自由argv、仓库地址或凭据。
- 实际清理使用可信管理员入口，与Agent Token隔离；不得把后端删除开放给模型工具，Operator Token不得进入agentd服务或模型上下文。
- 管理协调器持有控制日志写入锁，先取得Go维护预留屏障，再重新核验预览/保护引用并持久化PREPARED；随后启动固定后端操作、核验实际结果、写FORGOTTEN、释放屏障。未知结果可对账，在最终结果前不放行新备份。
- 仓库必须绑定唯一部署控制目录。当前历史实验共享仓库只允许预览，不因为本地eligible就删除；真实删除实验用新专用仓库，不能忽略其他控制目录可能持有的引用。
- 在新建专用合成仓库中实际验证预览、受保护拒绝、正常forget与prune、重启/锁冲突及剩余快照恢复；不删除旧报告所用快照或其他项目数据。
- 固定负载性能/流量、统一restic入口和完整V2十项逐项验收。当前控制模块不能当成V2-09已完成。
