# 检查点引用保护与受控清理

> Phase 9 V2，规格以文档43为准。已有本地引用投影、保留标记、离线预览、遗忘控制协议及owned helper新仓库组件验证；Go持久清理屏障和Operator入口已有本地/fake回归，Python协调器及真实联合验收未完成。默认运行仍不自动删除快照。历史真实服务证据见文档47。

## 1. 为什么不能按checkpoint_id直接删除

多份联合检查点可能指向同一个restic快照；仓库逻辑名称也可能是同一仓库的别名。清理以`repositoryCryptoId + 完整snapshotId`为组，检查所有已知引用。即使选中的checkpoint不是当前head，只要同组另一份是head，该快照仍受保护。

本账本只掌握当前控制目录的引用，不枚举MinIO对象，也不能授权删除其他部署或未知快照。后端还要核对固定仓库身份、真实snapshot及跨维护操作的串行屏障。不能用“本地预览eligible”替代这些执行证明。

## 2. 哪些引用必须保护

| 来源 | 当前处理 |
|---|---|
| 每条保留分支的head | 整组禁止遗忘 |
| 显式pin | 持久化`checkpoint.pin`；unpin只解除这一类引用 |
| 已保留恢复请求的source | RESERVED/FILES_READY/ATTACHED/FAILED都保留来源引用；没有自动释放功能 |
| 正在保存的检查点 | PREPARING/DATA_READY使预览暂时阻止所有清理 |
| 活跃历史恢复 | RESERVED/FILES_READY暂时阻止所有清理 |
| FAILED但已有data的检查点 | 已知孤立数据保留，不能当普通已提交旧版本清理 |
| 无法验证的Session引用 | 阻止该组清理，先查明控制数据问题 |
| 不在账本中的后端对象 | 不列作候选，不手工删除对象或哈希块 |

清理预览包含固定格式原因、完整组成员、逻辑仓库别名及当前文件恢复资格。没有用户自由文本原因、凭据、仓库URL或完整消息内容。

## 3. 历史提交与文件恢复资格分开

```text
历史checkpoint.state：COMMITTED，原件一直保留

文件资格：available
             ↓ checkpoint.forget PREPARED，fsync
         forget-pending
             ↓ 可信执行器实际forget成功后，写FORGOTTEN
          forgotten
```

- `prepare_forget`接受UUIDv4 gcId、精确仓库/快照及预览SHA256；重新计算当前预览，拒绝过期、被保护、未知或并发清理目标。
- 一条PREPARED同时绑定整组checkpointIds，先停止它们的文件恢复资格，再允许后续协调器执行删除。相同请求重试不重复追加；改绑定拒绝。
- `restore_point`、按旧node选检查点及新恢复请求都会检查文件资格。历史消息树与原始COMMITTED记录仍可读，不偷偷改用邻近文件版本。
- PREPARED后进程崩溃、后端失败或结果未知时，保持不可恢复及禁止新保存的状态，等待同一个管理请求对账；不能自动回滚为available。
- `complete_forget`是内部控制方法，本身不证明后端删除成功。目前只有合成测试使用它，没有HTTP/模型工具或CLI apply入口；未来可信协调器核验实际结果后才能调用。
- FORGOTTEN后不允许重新绑定同一已遗忘snapshot，后续正常新检查点可以继续沿当前未删除head递增revision。

预览SHA是当前引用投影的内容校验，不是授权令牌；日志checksum同样不是防恶意管理员的签名。原JSONL单写入锁、fsync和完整坏记录拒绝继续生效。新事件启用后不要交给不识别pin/forget事件的旧版本写入。

## 4. 可运行管理命令

先停止同控制目录的agentd；文件锁占用时命令拒绝，不接管或强制解锁。仅访问已存在的WSL原生私有控制目录，不自动初始化。

```bash
agentd/.venv/bin/python -m agentd.checkpoint_admin \
  --checkpoint-dir "$HOME/.local/share/sandboxd/<部署控制目录>/checkpoints" preview

agentd/.venv/bin/python -m agentd.checkpoint_admin \
  --checkpoint-dir "$HOME/.local/share/sandboxd/<部署控制目录>/checkpoints" pin 'cp-<uuid4hex>'

agentd/.venv/bin/python -m agentd.checkpoint_admin \
  --checkpoint-dir "$HOME/.local/share/sandboxd/<部署控制目录>/checkpoints" unpin 'cp-<uuid4hex>'
```

preview以只读文件描述符打开日志，保持排他文件锁，不chmod、不修断尾、不追加日志；pin/unpin使用正常单写入流程。读文件可能更新文件系统atime，不能把它描述为所有文件系统元数据都静止。两种模式都不访问NFS/MinIO、不调模型、不执行restic、不删除Session引用。

## 8. 带归属校验的后端helper组件

### 固定契约

`internal/backuphelper/ownership.go`新增`RepositoryOwner`：controller UUIDv4、完整repo crypto ID、不可删除的owner snapshot ID。它是部署配置及一致性绑定，不是管理员认证令牌，不能替代Operator授权或分支引用策略。

| helper操作 | 固定输入 | 行为 |
|---|---|---|
| init-owned | controller UUIDv4 | 只允许fresh restic init；生成固定/tmp标记文件并加密备份，返回归属三元组；已有仓库失败，不自动收编旧数据 |
| backup-owned | cp UUIDv4 + 归属三元组 | 验证归属后执行原备份，额外写固定controller tag |
| forget | 归属三元组 + 完整snapshot ID | 验证crypto、标记内容与全部快照归属；拒删标记，仅forget精确目标，再核对其余集合不变；已缺失目标可幂等确认 |
| prune | 归属三元组 | 同样验证归属，正常restic锁下prune；完成后标记和快照集合必须保持 |

同仓库出现无controller tag、其他controller、歧义controller或标记丢失时，在删除前拒绝。没有unlock、自由argv/路径/URL或直接S3块删除。旧init/backup/restore契约保留；Agent API没有新增forget/prune路由，默认v2镜像未切换。

仓库管理Pod使用既有gVisor/UID65532/drop ALL/只读根/无API Token/固定MinIO网络策略，init-owned/forget/prune只挂Secret和临时卷，不挂业务NFS。标记临时文件只在可信维护Pod中，归属结果和配置保存在沙箱外；Session/Task控制日志不会放进业务Pod。

## 10. 持久清理屏障与Operator入口（本地验证）

复用既有`WorkspaceBarrier`、维护Pod、完整spec/UID核验、健康Node与Lease停止证明、finalizer CAS及UID条件删除，不引入另一套执行系统。维护关联`workspace-<controller UUID>`只是日志键与Pod标签，不创建/挂载NFS目录，也拒绝注册为业务工作区。

```text
reserve（冻结仓库，不启动Pod）
    ↓ 管理协调器重新检查引用，持久化PREPARED（Python待接）
start → submitted → identified → stopped
                                  ↓ Wait核验真实结果并fsync CleanupResult
                                  ↓ Python写FORGOTTEN（待接）
                                finish → released

非零/超时/坏日志 → 保持冻结 → 确认旧Pod停止、清理同UID
                               → 显式retry固定目标的新job → reserved
```

- 全局互斥双向成立：已有备份/恢复时拒绝清理，清理未released时拒绝新备份/恢复；重启从原JSONL投影，不根据进程内锁猜测完成。
- 同gcId固定操作和精确snapshot；重试保持同目标，换jobId；历史gcId不可在后续请求中重新绑定，旧jobId不可再次当新尝试。成功已核验时禁止再执行重试。
- Wait要求真实成功Pod、固定restic版本、operation/owner/完整snapshot及明确forgotten或pruned结果；成功证明含实际维护镜像/Pod UID，先落盘再允许清理Pod。无结果时不接受“调用者说成功”。
- abort只确认停止，失败/未知不释放；没有成功证明不能finish。prune与forget共用同一仓库屏障，不能与备份并行；不提供unlock或自由参数。
- **预留撤销**：引用复核失败且尚未写PREPARED时，可用`cancel-reservation`。Go仅接受reserved，或abort后明确never-submitted的状态；先写停止，再写released+cleanupCancelled。已submitted/identified/实际执行过的Pod拒绝此路径。管理员协调器必须保证PREPARED后不调用它；Go不读取Python日志，不能单独证明这一条件。

固定HTTP路径：`GET /api/v1/repository/cleanup`；`POST /api/v1/repository/cleanup/{reserve|start|wait|abort|retry|finish|cancel-reservation}`。所有路径只接受Operator Token，Agent Token返回401。正文只有gcId、jobId、operation、snapshotId、timeoutMs，retry另需nextJobId；没有镜像、凭据、仓库地址、argv或success字段。timeout最多90秒；abort/retry/finish/撤销使用独立30秒清理窗口。GET普通workspace backup不暴露维护关联。

这不是可直接绕过引用策略的模型工具。Go负责固定后端及执行身份；可信管理员协调器负责锁住Python控制目录、head/pin/恢复源保护与PREPARED/FORGOTTEN。Operator本身是受信任管理员，不把拥有Operator身份的任意请求视为已完成引用审核。
