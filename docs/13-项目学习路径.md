# 项目学习路径

> 面向秋招的模块化学习计划。目标不是“把文档看完”，而是能沿代码解释机制、运行正反实验，并用自己的语言回答追问。

## 1. 学习原则

### 先全景，再链路，最后细节

先读 [项目全景与心智模型](24-项目全景与心智模型.md)，建立“不可信决策层—可信能力层—资源执行层”的地图。没有这张图时，很容易把 Python Policy 当最终安全边界，或把 SSH 错说成由 gVisor 保护。

### 每个模块做六个动作

~~~text
画数据流
  -> 读入口函数
  -> 解释为什么这样做
  -> 跑一个成功路径
  -> 跑一个拒绝/失败路径
  -> 说出生产化差距
~~~

### 破坏实验比被动阅读有效

实验只在个人学习分支进行，修改前记录基线，结束后恢复；不对主分支、真实主机或用户资源做破坏。

## 2. 先做 20 分钟预习

依次完成：

1. 阅读根 README 的架构图、当前状态和项目边界；
2. 阅读 [24 心智模型](24-项目全景与心智模型.md)；
3. 不看文档画出 Alertmanager 到 Diagnosis/Pending Plan 的链路；
4. 写下不理解的 10 个名词；
5. 后续只围绕这些问题查文档和代码。

## 9. 最小安全验证顺序

只做与学习目标相称的验证，不默认启动重型环境：

~~~bash
go test -p 1 ./...
go vet ./...
go build -p 1 ./...
uv run --project agentd --frozen python -m unittest discover -s agentd/tests
~~~

需要真实环境时，先运行 hack/check-resources.sh，再按 README 选择单个脚本；不要为了学习同时跑多个集群或高并发压测。

## 10. 最终毕业标准

### 第一档：能复述

- 说出架构和模块名；
- 知道九个工具；
- 能跑测试。

### 第二档：能解释

- 能沿调用链定位代码；
- 能解释每个安全层为什么不能互相替代；
- 能讲 CAS、DryRun、Context、Session 和 Prompt Injection。

### 第三档：能面试

- 能画图并回答追问；
- 能讲三个真实坑和证据；
- 能比较未采用方案；
- 能诚实说明生产边界；
- 面试官随机指出一个模块时，能在两分钟内找到入口代码。

达到第三档，这个项目才真正成为你的项目。
