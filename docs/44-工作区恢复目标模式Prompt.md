## V1 必须交付

- 业务文件以 Pod 挂载的专属 NFS 工作区为权威；agentd 文件工具通过 Go 的受限结构化接口操作，不默认双写本地 task 目录。
- workspace_id 独立于 task_id、attempt_id、sandbox_id 和 Pod UID；Pod 更换后工作区身份不变。
- Pod 故障和 agentd 重启后均自动接续未完成 Task，保留 task_id，新增 attempt。
- 持久化 Task 状态、分支/工作区绑定、调用用量及预留、原截止时间、恢复次数和取消；重启不重置预算或截止时间。
- 同 Task 多 attempt 的 Session 和 Trace 正确分组；恢复只读取完整交互边界，历史记录保留。
- 已确认接收的 steer/follow-up 按持久游标接续；用户取消优先；终态任务不复活。
- 旧写入者必须先确认停止或失去写能力，再绑定新实例；无法证明时阻止接管。
- 不重放历史工具；结果不明的写操作先核查 hash，不自动再次覆盖；不自动执行 Plan 或审批。
- V1 只保留最新文件状态。旧会话树可读取，携带工作区从旧节点恢复须明确拒绝。

## V2 必须交付

- 继续在 NFS 运行，采用受信任备份执行器同步使用 restic 备份至 MinIO 专用仓库；本地盘方案仅留作后续实验。
- 在完整工具轮次和最终诊断边界暂停工作区写入，持久化 Session 与文件快照后提交联合检查点。
- checkpoint_id 使用 UUIDv4；记录 branch_id、session_node_id、父检查点、分支 revision、工作区、Task/attempt、仓库及完整 snapshot_id、实际镜像身份与校验信息。
- 落实 PREPARING → DATA_READY → COMMITTED；仅完整提交后更新分支恢复头。相同请求重试幂等，部分备份和超时不当成功。
- 从有对应快照的旧节点分支时，新建分支和工作区；会话与文件指向同一版本，原目录/历史不覆盖。
- NFS 最新目录可用时不静默用旧备份覆盖；显式检查点恢复写入空目录，预算不回滚。
- 引用保护、受控清理预览及 restic forget/prune；默认不自动清理，不手工删除存储块。

## 实施顺序

1. M0：核对 WSL/Docker/kind/runsc、版本、资源、网络、NFS 与镜像兼容性；固定可复现依赖和环境证据。
2. M1：公共工作区身份、持久任务账本、受限文件 helper/RPC 和旧离线路径兼容。
3. M2：NFS 接线、Pod 接管、agentd 启动接续、预算与取消。
4. M3：逐项完成 V1 的 14 项验收、必要回归和三类联合回放。
5. M4：restic/MinIO、联合检查点和精确历史恢复。
6. M5：逐项完成 V2 的 10 项验收及固定工作负载性能测量。

每阶段形成可审查提交、中文学习说明和原始证据。V1、V2 分开开发/验收；最终保留同一套公共逻辑及可选择的运行模式，不复制两套 Agent。

## 权限、资源与费用

- 已授权本目标必要的本地测试、确定性 Replay、项目专用服务和单节点可控故障实验。
- 先检查资源，串行运行重操作；只操作明确属于本项目的资源，不清理其他容器/卷。
- 不运行外部付费 LLM/Jev，不沿用历史预算；密钥不打印、不记录、不提交。
- 保持 gVisor、非 root、Go 独立校验、路径/symlink/CAS/大小限制、RBAC 与审批门。业务文件持久化不授权生产系统写入。
- 保留 Session/记忆/控制日志在沙箱外；旧数据通过显式映射迁移，不直接删除。
- 不引入 LangGraph、数据库、消息队列、动态插件、任意 Shell、Operator、多租户或生产级 HA。
- sudo 与系统变更遵守 GOAL；关键路线不兼容、权限扩大、数据删除或外部费用需要先向用户说明并确认，同时继续独立工作。
