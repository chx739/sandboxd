## 2. OpenSearch Benchmark

日志功能最新复测见 [40用例原始报告](evidence/phase25-logs-bounded-results.json)：40/40，集合 Precision/Recall 和聚合正确率均1.0，P50=2.16ms、P95=3.02ms。使用合成日志与固定正确参数；参数 Schema 接受率不代表模型生成参数准确率。工具默认3条且拒绝超过3500字节的响应，相关超限测试已通过。

按官方 [自定义 workload](https://docs.opensearch.org/3.0/benchmark/user-guide/working-with-workloads/creating-custom-workloads/) 与 [run 命令](https://docs.opensearch.org/latest/benchmark/reference/commands/run/) 使用独立工具环境，避免其 numpy 等依赖影响推理环境。

```bash
uv venv .cache/ops-benchmark-venv --python agentd/.venv/bin/python --seed
.cache/ops-benchmark-venv/bin/python -m pip install -r agentd/logs/benchmark/requirements.lock
BENCHMARK_HOME="$HOME/.local/share/sandboxd/benchmark" \
  .cache/ops-benchmark-venv/bin/opensearch-benchmark run \
  --pipeline=benchmark-only \
  --workload-path=agentd/logs/benchmark/workload.json \
  --target-hosts=127.0.0.1:9201 --distribution-version=2.19.6 --offline \
  --results-format=csv --results-file=.cache/ops-benchmark.csv \
  --client-options=timeout:10 --on-error=abort
```

先导入固定日志。该 workload 不执行删除、创建或写入索引，只对固定 hash 索引查询。1客户端、目标20 ops/s；每个操作20次预热，100次测量。全工具完成约38秒，包含调度/遥测时间。

| 操作 | P50 latency ms | P99 latency ms | 错误率 |
|---|---:|---:|---:|
| service-errors | 4.76 | 6.27 | 0% |
| all-service-counts | 3.75 | 6.07 | 0% |
| error-timeline | 3.34 | 5.37 | 0% |

目标吞吐为人为限速，**20 ops/s 不是系统吞吐上限**。数据仅720条、热缓存、小并发；AMD Ryzen 5 9600X / WSL2，OpenSearch 容器2 CPU/2GiB，JVM512MiB，其他历史服务仍运行。

原始 [CSV](evidence/phase23-opensearch-benchmark.csv)、[运行 JSON](evidence/phase23-opensearch-benchmark-raw.json)、[环境](evidence/phase23-opensearch-benchmark-environment.json) 保留。CSV 的 Doc count=748 是含系统索引的集群遥测；目标索引单独 `_count` 为720。未把不同口径拼成工作负载数据量。

## 3. Ragas 与生成评测

Ragas 是离线评测依赖，不参与线上 Agent 编排。固定旧版兼容的 LangChain/OpenAI/Instructor 组合只存在于这个隔离环境；没有给 Runtime 引入 LangGraph。

```bash
uv venv "$HOME/.local/share/sandboxd/ragas-venv" --python agentd/.venv/bin/python --seed
"$HOME/.local/share/sandboxd/ragas-venv/bin/python" -m pip install -r agentd/ops_eval/requirements.lock
RAGAS_DO_NOT_TRACK=true LANGCHAIN_TRACING_V2=false LANGSMITH_TRACING=false \
  "$HOME/.local/share/sandboxd/ragas-venv/bin/python" -m unittest agentd.ops_eval.test_protocol -v

# 仅预览，不需要 Key、不联网
agentd/.venv/bin/python -m agentd.ops_eval.generation
agentd/.venv/bin/python -m agentd.ops_eval.generation --ids all
```

`generation.py` 输入已保存的检索结果和固定 QA hash，模型只接收问题与相应检索片段，不接收参考答案。无检索模式不给文档；RAG 模式给排名前三的实际 snippet。生成答案为结构化 JSON，包括回答、步骤、适用条件、缺失信息和引用。

评价分开保存：

- [Ragas FactualCorrectness](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/factual_correctness/)：两种生成模式都与**候选参考答案**比较，F1 模式；参考不完善会影响评分。
- [Ragas Faithfulness](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/faithfulness/)：仅 RAG 对其实际上下文评价；无检索记为不适用，不假填0分。
- 每个关键步骤是否覆盖、每个引用是否支撑断言、适用条件、无依据确定性、证据不足处理：独立运维 rubric，保存模型理由与逐项结果。
- 引用 ID 是否来自实际返回、是否需要引用、abstained 是否匹配候选标签：确定性检查，与语义支持评分分开。

适配器用 Ragas 官方指标类；通过受预算限制的自定义 LLM 实现结构化生成接口。没有 SDK 自动重试或静默模型修复。Ragas 默认英文指标模板未额外做付费翻译，中文答案评分仍需抽样人工核对。NaN 转为 null，不冒充0分。

默认计划只选6题做**生成测评冒烟验收**，含精确、步骤、多文档、信息不足；不是60题完整生成榜单。`--ids all` 可预览完整60题。每题两种答案、最多14个预期请求，额外次数上限仍由硬门限制。

生成时间单列；检索耗时来自之前的独立检索报告，二者相加只能叫组件估计，不能冒称同一次端到端实测。真正联合任务端到端时间由下一节 Runner 记录。

## 4. 联合 Live 测评

```bash
agentd/.venv/bin/python -m agentd.ops_eval.live_agent
```

固定3个场景、最多6轮/任务、18次 DeepSeek v4-pro、每任务120秒。使用 JSON action 适配器将模型输出转换为当前 Runtime 的 ToolCall；只注册日志和知识插件。这个适配器用于评测，不替换线上原有原生 Tool Calling Gateway。

使用真实模型与实际本地 Milvus/OpenSearch，Sandbox 仅为生命周期替身，不访问真实集群。记录工具选择、参数与固定场景一致性、日志独立 oracle、必要错误证据、适用文档和引用 ID。事实/假设的语义评价有人工/模型审核清单，不能由几个关键词匹配宣称通过。

这个最小 JSON 适配器不向 Runtime ModelUsage 填供应商 token；实际费用/用量以独立 calls.jsonl 为准，不能把 Runtime 的0当成无费用。

## 5. 费用与失败停止

所有 Live CLI 默认预览。执行必须显式 `--execute --max-usd ... --expected-sha256 ... --output <新文件>`；只在用户批准对应模型、数据、次数、预算之后运行。Key 通过进程环境 `AGENTD_LLM_API_KEY` 注入，不写到命令、仓库或输出。

- 固定输入哈希：防止批准后换题/换上下文。
- 逐请求之前：检查模型白名单、输入字节、输出 token、剩余调用次数与费用预留，先落盘 attempt，再联网。
- 失败：不自动重试，保留未知调用的保守费用预留并停止；HTTP 成功但 JSON/Schema 无效也停止，不自发追加修复调用。
- 逐请求之后：保存可见答案/裁判理由与 token 计数；不保存认证 Header、Key 或隐藏推理字段。
- 不覆盖旧账本/结果；崩溃时的 attempt 视为未决消费，先核对再恢复。

单价按 [DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/) 2026-09-29峰时、未命中缓存费率保守计算：Flash input/output 为 $0.30/$1.20，Pro 为 $1.32/$3.96（每百万tokens）。账本估算不是供应商硬性账单封顶。模型别名可能随供应商升级而变，固定输入和模型名也不等于底层权重永不变化。
