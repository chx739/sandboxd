## 4. 本轮补充实验的边界

入口：

```bash
# 项目kind/gVisor/NFS/专属MinIO及其仓库外配置先就绪；不需要外部LLM Key。
bash hack/workspace.sh build-storage
agentd/.venv/bin/python -m agentd.workspace_checkpoint_acceptance \
  --output .cache/<新的拒绝验收报告>.json
/usr/bin/python3 agentd/workspace_checkpoint_acceptance_audit.py \
  --source .cache/<拒绝验收报告>.json --output .cache/<新的独立审计>.json
```

夹具每次新建`deployments/acceptance-<UUID>`和专属`owned-deploy`仓库前缀，只操作自己新建的合成数据，旧输出不覆盖。它使用真实Agent ASGI处理器/TaskStore/Runner、固定Replay及真实Go TCP/存储，未冒充Agent TCP、Live模型或生产故障。

1. 首次完整save成功后，管理夹具重复同一真实调用，核对返回CP/snapshot/revision、Go/CP日志hash和RPC序列，仅允许多一次幂等Finish。
2. 暂留该完整轮次窗口，实际API拒绝活动Session切换；直调Go也拒绝覆盖活动工作区，原日志和文件保持。
3. 最终Task成功、CP2成为head后，在本轮新Session引用中注入坏内容；原字节先另存，API409后恢复，原Task不追加调用。
4. 在三个新目标中验证不存在snapshot、错误manifest和错误imageID。前两者为空且隔离；后者文件版本恢复成功，但实际镜像不符时绑定/文件工具409，再通过Go确认该Pod停止，没有静默改用实际镜像。
5. Agent lifespan关闭后，可信管理协调器仅遗忘本轮新建CP1的非head快照。重新打开处理器后，旧CP恢复409、历史消息200；head CP2、原文件/Task/Session保留。Operator不传入App设置或模型；这是管理夹具，不声称管理员与ASGI运行在两个独立OS进程。

独立审计[报告](evidence/phase9-v2-acceptance-audit.json)重算Go55/CP11/Task21条日志、原始日志前缀、镜像和隔离状态，并实际核对仓库保留marker+head两个snapshot及`check --read-data`。快照缺失/manifest错误是可信Go/存储层负例；遗忘和Session引用错误另外经过实际Agent API，不把所有层的测试都统称为端到端。

## 6. 面试时的准确讲法

V1解决“执行Pod可替换、任务和最新文件可接续”；V2在NFS之外增加“完整会话边界与不可变文件快照的联合恢复点”。Task是逻辑运行，attempt是故障接续次数，checkpoint是可恢复边界，restic snapshot是文件版本，不能相互替代。

最关键的正确性来自持久意图、完整消息边界、物理停止证明、原预算和单条COMMITTED投影，而不是UUID大小、Pod标签或向量检索。数据未提交、来源校验失败或旧写入者未确认停止时，系统保留证据并停止，不伪造恢复成功。

限制：单节点/单部署、控制盘仍需可用、NFS/MinIO不提供HA、同步检查点有明显等待、64MiB/512项/单文件256KiB的有界文本工作区、未实现任意Shell或进程内存恢复。真实模型效果、Phase8人工审核与未授权Live评测是另一个目标，不用本轮Replay成绩替代。
